2.5 DATA FETCHING ARCHITECTURE
──────────────────────────────

Problem: Zero Centralized State

  Current: Every component independently fetches
  Result:
    - No cache → repeated API calls
    - No sync → data inconsistency across views
    - No optimistic updates → slow UI
    - No real-time → requires manual refresh

Solution: Implement SWR hooks system
  - /src/hooks/use-api.ts
  - /src/hooks/use-students.ts
  - /src/hooks/use-grades.ts
  - etc.

Impact: 40% faster perceived performance, consistent state

═══════════════════════════════════════════════════════════════════════════════

2.6 API ROUTES INCONSISTENCY
──────────────────────────────

Current Issues:
  • Response format varies:
    - Some routes: { data: [...] }
    - Some routes: bare array [...] 
    - Some routes: { success, data, error }
  
  • HTTP status codes inconsistent:
    - Validation errors: some 400, some 422
  
  • Pagination non-standard:
    - Some routes ignore it
    - Some implement offset/limit
    - No cursor-based option

  • Error messages: No standard format

Solution: Create standardized response middleware
  Standard format: { success: bool, data, error?, pagination? }
  Apply to ALL 100+ routes
